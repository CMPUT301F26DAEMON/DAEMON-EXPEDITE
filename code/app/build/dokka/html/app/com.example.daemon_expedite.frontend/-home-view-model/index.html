HomeViewModel

class HomeViewModel : ViewModel

Data for the entrant and admin home screens: the search text and the campsites to show. Each home screen gets its own instance.

Loads suggested campsites on start, and searches again whenever search text or filter options change. Also reloads quietly each time the screen is shown again (see onScreenShown), because this ViewModel lives as long as the Home screen, which stays at the bottom of the back stack.

Campsites owned by the signed-in user are left out (see setViewer): you can't book your own campsite, so entrant home doesn't offer it. They still show on the owner home page. Admin home never calls setViewer, so it lists every campsite, the admin's own included. Searching waits until the user stops typing for SEARCH_DELAY_MS so the database is not queried on every key press.

fun onScreenShown()

Call each time the Home screen appears. The first time does nothing (the start-up search already covers it). After that, for example coming back from the owner view after registering a campsite, it reloads in the background: the current list stays on screen until the new one arrives, and stays put if the reload fails.
